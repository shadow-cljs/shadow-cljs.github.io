The `:target :react-native` produces code that is meant to integrate into the default `react-native` tooling (eg. `metro`). When using Expo or another wrapper, configure its entry file to load the generated output and register the app's root component.

You will need the same basic <<config,main configuration>> as in other targets (including
source paths in `deps.edn`), the build specific config is very minimal and requires at least 2 options (besides `:target` itself)

[horizontal]
`:init-fn`:: (required). The namespace-qualified symbol of your apps init function. This function will be called once on startup and should probably render something.
`:output-dir`:: (required). The directory used to write output files.

Keep `:output-dir` separate from hand-written application sources because its files are generated.

.Sample :react-native config
```
{:deps true
 ...
 :builds
 {:app
  {:target :react-native
   :init-fn demo.app/init
   :output-dir "app"}}}
```

When compiled this results in a `app/index.js` file intended to be used as an entry point for the `react-native` tools. During development the `:output-dir` will contain many more files but you should only reference the generated `app/index.js` directly. A `release` build will only generate the optimized `app/index.js` and requires no additional files.

== React Native

A plain React Native project loads the generated `app/index.js` from its JavaScript entry file. The CLJS init function must register the root component using React Native's `AppRegistry`. The following repository illustrates the integration, but its dependency versions and tooling setup may be historical:

- https://github.com/thheller/reagent-react-native

== Expo

https://expo.dev/[Expo] can load the generated output as a custom entry point. For a project without Expo Router, set `main` in `package.json` to the output file:

```json
{
  "main": "./app/index.js"
}
```

The CLJS init function must register the root component. See https://docs.expo.dev/versions/latest/sdk/expo/#registerrootcomponentappkey[Expo's registerRootComponent documentation]. Expo Router projects have their own entry-point conventions; the setup above assumes the CLJS init function owns application startup.

These older repositories illustrate shadow-cljs integration, but their `expo init` commands and `app.json` `entryPoint` configuration should not be copied into a current project:

- https://github.com/thheller/fulcro-expo
- https://github.com/thheller/reagent-expo

`shadow.expo/render-root` registers a React component and accepts a React element to render. This helper requires the `expo` and `create-react-class` npm packages in addition to the React Native project's dependencies.

.From the Reagent https://github.com/thheller/reagent-expo/blob/2c73ed0513a8f5050b250c0c7e53b9ae7543cee9/src/main/test/app.cljs#L34-L40[example]
```
(defn start
  {:dev/after-load true}
  []
  (expo/render-root (r/as-element [root])))

(defn init []
  (start))
```

`init` is called once on startup. Since the example doesn't need to do any special setup it just calls `start` directly. `start` will be called repeatedly when `watch` is running each time after the code changes were reloaded. The `reagent.core/as-element` function can be used to generate the required React Element from the reagent hiccup markup.

== Hot Code Reload

React native requires to reload not only compiled files and files explicitly requiring those, but also their transitive dependents, for changes to take effect. To accomplish this, use `:reload-strategy` option as in <<reload-strategy, Hot Reload of Transitive Dependents>>.
